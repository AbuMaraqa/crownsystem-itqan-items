## 1. Importer: the main item must stay a real product
Measured on the real sample: pieces import perfectly, but `a_al` loses cost, barcode, unit, shelf and inactive state, because the importer turns it into a category and `MainProductLinker` later creates an empty main product.
- Import each `a_al` that has children as a real product in the same run, with cost, barcodes, unit, shelf, note and active state, `pricing_type=weight`, sku = legacy id. Keep the twin category with the same code if the Tree page relies on it (read `twinId`, `twinIds`, `categoryProductsQuery`), and link the main product the way `createMainFromCategory` does so the tree looks unchanged. The linker must then find it by sku and create nothing.
- `b_al` directly under a `c_cont` (real data: 1,345 rows) keeps today's behaviour: linker creates a main item from the category.
- `c_cont` is always a category, even with no children (9 sample rows wrongly became products).
- Add tests with these cases.

## 2. Price on a line: same order as Itqan
Add a `PriceResolver` entry point for document lines, used by sales and purchase line payloads (`ProductSearch::salesItemPayloads`, `invoiceItemPayloads`, and the callers in the items grid):
1. Last price for this party and item, from their most recent posted document line. Derive it from document lines (see `CustomerHistoryService::itemPrices`); do not add a copy table like Itqan's `itemslastprices`. Add an opt-in flag on the party, matching Itqan's per-account-type `islastprice`. Find how customers and customer groups are modelled and put it where it fits.
2. Otherwise the party's price list (add a nullable `price_list_id` where it fits) using `PriceResolver`: sell side for sales, buy side for purchases.
3. Otherwise today's behaviour (`sale_price`, or cost plus customer margin), so existing customers do not break. Report this as a deliberate fallback.
For weight lines the price belongs to the main item. No party selected: no automatic price, as in Itqan.

## 3. Weight line amount
Amount = actual weight x kg price. **Owner's explicit decision: amount is zero when actual weight is empty**, even when pieces give a calculated weight. Change `WeightPieces::line` and `pricingWeight`, and the matching grid JavaScript, consistently. Stock weight posted to the ledger stays as it is today; only the amount changes. Add a clear non-blocking notice on the line ("الوزن الفعلي فارغ"). Do not bypass existing posting validation: if a service refuses a zero-total document, keep that refusal and report it. Update tests asserting the old fallback, listing each one. Do not change posted documents.

## 4. Item tree: right-click menu by type
On `Modules/Items/Livewire/Pages/Product/Tree.php` and its blade, add a context menu matching the table in the spec, section 2: edit, add category, add item, add piece under a main item, copy main item with its pieces, delete, move, item movement, plus reports only where a page already exists.
- Move: re-parent only; not allowed for main items or pieces. A moved item gets a new code via `ItemCode` and, for a category, its children too, in a transaction. Refuse a move into its own subtree.
- Copy main item: new main with new code, all pieces with new codes, same barcodes (they may repeat), no stock or documents.
- Delete: use `deletionBlocker`. An item with document lines is deactivated, matching Itqan, rather than deleted.
- Gate every action with the module's permissions, in the Livewire method as well as the UI.
- Do not regress the tree tests.

## 5. Add item from the tree
Adding under a main item fixes the type to piece and the parent to that main item. Adding a category fixes it to category. A repeated name is allowed for pieces only: fix the slug so a repeated piece name does not raise a slug error (generate a unique slug). Code is automatic and read-only. Check the existing card form first and change only what differs.

## 6. Apply to other colours
When saving a piece, offer "تطبيق على نفس المقطع في الألوان الأخرى": list products with the same barcode under other main items, and apply only weight per metre, length and name to those the user ticks, in a transaction. Never touch price or stock. Default is off.

## 7. Keep pieces when changing the main item on a line
In the items grid, when a weight line's main item changes, offer: clear pieces; keep same rows; or match by name under the new main item (unmatched pieces are listed, not silently dropped). Match Itqan's default: clear, unless the user chose keep.

## 8. Barcode entry on documents

A piece adds under its main item (see `addSubItemRow`). Many matches: show a picker, because barcodes repeat across colours by design. None: a clear message with an "add item" link if permitted.
